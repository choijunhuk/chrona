# Stage 6 — 집중 타이머 + 잠들기 전 브리핑

> **선행**: Stage 5 완료 및 머지
> **브랜치**: `stage-6-timer-briefing`
> **목적**: 통계의 원천 데이터(`focus_sessions`)를 만들고, 하루를 닫는 루틴을 추가한다.

---

## 1. 집중 타이머

### 1-1. 왜 어려운가
RN의 `setInterval`은 앱이 백그라운드로 가면 신뢰할 수 없다. 화면을 끄면 멈춘다.
**해결: 타이머의 진실은 "시작 시각"이고, 남은 시간은 매번 계산한다.** 카운트다운 변수를 감소시키는 방식은 쓰지 않는다.

```ts
// 나쁨:  remaining -= 1  (백그라운드에서 멈춤)
// 좋음:  remaining = endAt - Date.now()  (항상 정확)
```

여기에 **포그라운드 서비스**로 알림창에 남은 시간을 표시하면 백그라운드에서도 살아있는 것처럼 동작한다.

### 1-2. 구현

```
/timer  (전체화면 모달)
  ┌──────────────────────┐
  │                      │
  │      24:37           │  ← 거대한 숫자, tabular-nums
  │   ◯ 원형 프로그레스    │
  │                      │
  │   자료구조 복습        │  ← 연결된 일정 (선택)
  │                      │
  │  [일시정지]  [종료]    │
  └──────────────────────┘
```

- 프리셋: 뽀모도로 25/5, 50/10, 커스텀
- 원형 프로그레스는 Reanimated + `react-native-svg`의 `strokeDashoffset`
- **1초마다 리렌더하지 않는다.** 초 단위 텍스트만 갱신, 원은 worklet에서 연속 애니메이션
- 화면이 꺼져도 되도록 `expo-keep-awake`는 **쓰지 않는다** (배터리). 대신 포그라운드 서비스에 의존

### 1-3. 포그라운드 서비스

Stage 0에서 만든 서비스 인프라 재사용. 채널은 `chrona.timer`.

```
알림창 표시:
  집중 중 · 자료구조 복습
  24:37 남음
  [일시정지] [종료]
```

- 알림 갱신은 **10초마다** (1초마다 하면 배터리·로그 폭발)
- 알림의 액션 버튼으로 앱을 열지 않고도 일시정지/종료 가능
- 종료 시 **서비스 즉시 stop** (마스터 §6)

### 1-4. 완료 처리

- 완료 시 짧은 알람 (`chrona.alarm` 채널, `loopSound: false` — 3초 정도)
- 햅틱 success
- `focus_sessions`에 기록: `started_at`, `ended_at`, `planned_minutes`, `completed: true`
- 중도 종료 시 `completed: false`로 기록 (통계에서 구분)
- 휴식 시간 자동 시작 여부를 물어본다 (기본 끔 — 자동 시작은 강압적)

### 1-5. 일정 연결

- 홈이나 일정 상세에서 "집중 시작" → `focus_sessions.event_id` 연결
- 시간표 과목에서 시작하면 그 과목 시간으로 누적 (Stage 7 통계의 핵심)
- 연결 없이 시작하는 것도 허용 (`event_id = null`)

### 1-6. ★ 타이머 중 알람 충돌

마스터 §9 규칙:
- **타이머 서비스는 유지**하고, 알람을 그 위에 전체화면으로 띄운다
- 알람 해제 후 타이머 화면으로 복귀
- 타이머는 백그라운드에서 계속 카운트 (시작 시각 기반이므로 자동으로 정확)
- 두 포그라운드 서비스가 동시에 뜨는 것은 정상 (채널이 다름)

**이 케이스를 반드시 실기기에서 테스트한다.**

## 2. 잠들기 전 브리핑

### 2-1. 스펙

- 매일 23:00 (`app_settings.briefing_time`으로 변경 가능)
- **알람 모드 아님.** `chrona.reminder` 채널, 조용한 알림 1건
- 탭하면 내일 타임라인으로 딥링크 (`/calendar?date=내일`)

내용:
```
내일 일정 3개 · 첫 일정 09:00
자료구조 · 운영체제 · 저녁 약속
마감 임박: 운영체제 과제 D-1
```

- 일정이 없으면 "내일은 일정이 없어요" (알림을 건너뛰지 않는다 — 오히려 이게 유용한 정보)
- 마감 3일 이내 과제가 없으면 해당 줄 생략

### 2-2. 구현

- 브리핑도 **알람 재계산 파이프라인에 합류**시킨다. 별도 스케줄러를 만들지 않는다
- `computeAlarmTimes`에 브리핑 항목을 추가 (30건 상한을 공유)
- **내용 생성은 예약 시점에 한다.** 마스터 §3.5 규칙 — 발화 시점에 DB를 못 읽으므로, 예약할 때 내일 일정을 조회해서 payload에 문자열로 담는다
- 따라서 **하루 중 일정이 바뀌면 브리핑 내용도 재생성**된다 (재계산 트리거로 자동 처리됨)

### 2-3. 설정

`/more` 하위:
```
잠들기 전 브리핑
  사용                [토글]
  시각                23:00
  주말에도 보내기       [토글]
```
